# LeetCode in Parens

![CI](https://github.com/AF2B/leetcode-in-parens/actions/workflows/ci.yml/badge.svg)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)
![Racket](https://img.shields.io/badge/Racket-CS-9f1d20.svg)

Все бесплатные задачи LeetCode, которые принимают Racket, решённые в скобках.
Каждое решение — идиоматичный Racket, покрытый тестами rackunit, и часто
решённый более чем одним способом — грубой силой, оптимизированно,
рекурсивно — рядом, в одном файле. Сборка, линтер, форматирование и тесты
запускаются при каждом pull request.

## Зачем несколько подходов к одной задаче

Решить задачу один раз — доказательство того, что вы нашли ответ. Решить её
ещё раз через грубую силу, ещё раз в оптимизированном варианте, ещё раз
рекурсивно (или любым другим возможным способом) — доказательство того, что
вы понимаете, *почему* ответ работает, и оставляет ориентир для того, как
одна и та же идея выглядит при разных ограничениях. Это не обязательное
требование для каждой задачи, но структура готова к этому всегда, когда это
того стоит.

## Структура репозитория

```
solutions/
  easy/
    two-sum/
      README.md        # краткое условие своими словами, ссылка
      meta.rktd        # id, slug, название, сложность, темы, подходы
      solution.rkt     # все подходы; первый — канонический
      test.rkt         # тесты rackunit
  medium/
  hard/
```

Задачи лежат прямо в папке той сложности, которую им присвоил LeetCode, и
названы собственным slug LeetCode (тем, что в URL задачи). Slug — уникальный
ключ задачи; номер задачи хранится в `meta.rktd` и в заголовке README.
Задача — это одна папка ровно с четырьмя файлами, никогда не папка на каждый
подход: каждый подход — это отдельная функция в том же `solution.rkt`,
покрытая тем же `test.rkt`.

Веб-интерфейс GitHub обрезает папки, в которых больше 1000 элементов, а
`medium/` их превысит. Используйте [PROBLEMS.md](PROBLEMS.md) или нажмите `t`
на странице репозитория, чтобы найти задачу.

## Запуск локально

Требования: Racket CS (версия, зафиксированная в
[`.github/workflows/ci.yml`](.github/workflows/ci.yml)).

```bash
raco pkg install --auto rackunit-lib fmt review

raco test solutions/easy/two-sum   # одна задача
raco test solutions                # всё
```

## Соглашения

- Только Racket: `#lang racket/base` с явными `require`.
- Входная функция сохраняет точное имя и контракт из шаблона LeetCode для
  Racket, чтобы решение можно было вставить в редактор.
- Каждая задача содержит `test.rkt`; решение без тестов не считается
  завершённым.
- `raco review` без предупреждений и `raco fmt` без изменений.
- Conventional Commits на английском, одна задача — один pull request.

Полные правила — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Вехи

Аннотированные git-теги отмечают прогресс: `solved-100`, `solved-250`,
`solved-500`, `solved-1000` и так далее, а также `easy-complete`,
`medium-complete` и `hard-complete`, когда сложность пройдена целиком.

## Область и правовые вопросы

В область входят все бесплатные (не premium) задачи, которые принимают
Racket. Задачи, не принимающие Racket, и premium-задачи пока вне области.

Условия задач принадлежат LeetCode. Этот репозиторий ссылается на каждую
задачу и пересказывает её своими словами; он не копирует условия и тестовые
данные сайта. Репозиторий не связан с LeetCode.

## Участие в проекте

Это личная витрина, поэтому решения написаны самим автором. Исправления
приветствуются — неверный ответ, недостающий тестовый случай, опечатка — см.
[CONTRIBUTING.md](CONTRIBUTING.md). Альтернативные решения от третьих лиц не
принимаются.
